How a Browser Mouse Jiggler Works

Why computers go idle, how monitoring software detects inactivity, and the three browser techniques StayAwake uses to keep you active.

The average office worker loses 45 minutes per week to unnecessary re-logins caused by screen locks. For remote workers, the problem is compounded: your Slack goes Away, your manager notices, and suddenly you're explaining why you were "offline" for 12 minutes during a deep-focus work session. A mouse jiggler solves this — and understanding how it works helps you use it confidently.

Why Computers Go Idle: The Operating System Timer

Every modern operating system — Windows, macOS, and Linux — maintains an idle timer. This timer measures the number of seconds since your last qualifying input event: a mouse movement, a keyboard press, or a touch event. When the timer reaches a threshold you've configured (or your employer has set via Group Policy), the OS takes action: it dims the display, locks the screen, suspends the session, or reduces CPU performance.

The default thresholds vary: Windows often defaults to 5 minutes for lock and 15 minutes for sleep. macOS defaults to 2 minutes for display sleep. Corporate-managed devices are frequently set more aggressively — sometimes as little as 90 seconds — to comply with security policies.

The key insight is this: the idle timer is reset by hardware input events from your mouse and keyboard. This is exactly the mechanism that a mouse jiggler exploits — it generates synthetic activity that continuously resets the timer.

How Remote Monitoring Software Detects "Away" Status

Applications like Slack, Microsoft Teams, and Zoom don't implement their own idle detection. Instead, they query the operating system directly. On Windows, Teams calls GetLastInputInfo(). On macOS, it queries IOHIDGetParameter. Both return the system's idle time — the same timer we discussed above.

When this value exceeds the app's threshold (typically 5 minutes for Slack and Teams), the app changes your presence status from Active to Away. This status is then visible to all of your colleagues and managers in real time.

Some advanced employee monitoring tools go further, tracking active window time, keystroke frequency, and mouse movement velocity. However, the majority of corporate tools — including Teams, Slack, and Zoom — rely exclusively on the OS idle timer, which is exactly what a mouse jiggler targets.

The Three Techniques StayAwake Uses

1. Wake Lock API (Chrome & Edge on HTTPS)

The Screen Wake Lock API is a modern web standard that allows a web page to request that the operating system keep the display active. When StayAwake calls navigator.wakeLock.request('screen'), the browser forwards this request to the OS, which prevents the screen from dimming or turning off for as long as the Wake Lock is held.

This is the most direct and reliable method available in a browser. It works even when the tab is backgrounded or minimized, because the Wake Lock is held at the OS level, not the rendering thread level. The catch: it requires HTTPS and is currently supported in Chromium-based browsers (Chrome 84+, Edge 84+). Firefox and Safari do not yet implement the full API.

2. Canvas Animation Loop

For browsers without Wake Lock support, and as a supplementary layer in all browsers, StayAwake runs a continuous requestAnimationFrame loop on an invisible 2×2 pixel HTML canvas element. This element is positioned off-screen and rendered with near-zero opacity, making it invisible to the user.

The animation loop continuously modifies a single pixel's color value — a trivial change that nonetheless keeps the browser's rendering engine active and prevents the browser from entering a low-power suspended state. On most operating systems, an active browser rendering loop generates enough CPU activity to prevent the idle timer from reaching its threshold.

3. Pointer Event Simulation

At your chosen interval (every 30 seconds, 1 minute, 2 minutes, or 5 minutes), StayAwake dispatches a synthetic MouseEvent of type mousemove on the document. The event moves the simulated cursor position by ±1 pixel in alternating directions, creating a micro-oscillation that is invisible to the human eye but detectable as input activity.

This technique is the most direct emulation of physical mouse movement and is effective across all browsers. It is used as a fallback in Firefox and Safari, and as a redundant layer in Chrome and Edge alongside the Wake Lock API.

Why a Browser-Based Jiggler Is Safer Than Software

Downloadable mouse jiggler software must install itself on your device, often requiring administrative privileges. On a corporate-managed laptop, this is frequently blocked by endpoint protection software like CrowdStrike, Defender for Endpoint, or Jamf. Even if installation succeeds, the process appears in your system's running process list — visible to IT monitoring tools.

StayAwake runs entirely within your web browser. It creates no files on your device. It does not appear in the Windows Task Manager process list or macOS Activity Monitor as a separate process. From your operating system's perspective, it is simply a browser tab — indistinguishable from reading a news article or watching a video.

Limitations to Be Aware Of

No browser-based mouse jiggler is perfect. Here are the honest limitations:

  • Deep sleep / hibernation: If your OS is configured to hibernate (not just sleep) after inactivity, the Wake Lock API may not prevent it on all systems. Canvas animation and pointer events generally suffice for sleep prevention.
  • Advanced monitoring software: Some enterprise tools (Teramind, ActivTrak) analyze typing patterns and keystroke velocity. These cannot be fooled by a browser-based jiggler, as they track actual keyboard input, not OS idle state.
  • Tab must remain open: The browser tab must stay open (though it can be minimized). Closing the tab stops all jiggling techniques immediately.
  • Corporate proxy blocking: In rare cases, company proxy rules might block access to specific websites. In this situation, consider downloading a simple offline version or using an alternative.

Is Using a Mouse Jiggler Ethical?

This is a fair question, and the answer depends on context. StayAwake is designed for use cases where idle detection creates a false picture of your activity — for example, when you're reading a long document, on a phone call, or thinking deeply without touching your keyboard. In these cases, the OS idle timer misrepresents your real work state, and a jiggler corrects for that.

We do not condone using StayAwake to deceive employers while not working. Use it responsibly, in alignment with your organization's remote work policy. Many companies have no policy specifically covering browser-based productivity tools, but when in doubt, check with your manager or HR team.
